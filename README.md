# Детекция спама с помощью машинного обучения

Курсовой проект по автоматической классификации англоязычных SMS на обычные сообщения (**ham**) и спам (**spam**). В Jupyter Notebook выполнен полный цикл исследования: от очистки и анализа данных до сравнения восьми моделей и подбора гиперпараметров.

**Основной результат:** модель `MultinomialNB` с TF-IDF и параметром `alpha=0.1` получила **Accuracy 98,51%** и **F1-score 0,9426** на тестовой выборке. Значения приведены по сохранённым результатам ноутбука; особенности оценки описаны в разделе «Ограничения».

## Задача проекта

Исследовать, насколько эффективно классические алгоритмы машинного обучения распознают спам в коротких текстах, и выбрать модель с хорошим соотношением качества и скорости обучения. Особое внимание уделяется обнаружению спама при дисбалансе классов и количеству ложных срабатываний.

Основной файл работы — [Jupyter Notebook](Курсовая_работа_Гильманов_ПМ24_1_.ipynb). Он содержит код, пояснения, графики и результаты экспериментов.

## Данные

Использован набор **SMS Spam Collection** с англоязычными сообщениями. В работе указан [источник на Hugging Face](https://huggingface.co/datasets/ucirvine/sms_spam/viewer/plain_text/train).

| Характеристика | Значение |
|---|---:|
| Исходное количество сообщений | 5 572 |
| Удалено дубликатов | 415 |
| Сообщений после очистки | 5 157 |
| Обычные сообщения — ham | 4 516 (87,57%) |
| Спам — spam | 641 (12,43%) |
| Пропущенные значения | Не обнаружены |

Ноутбук загружает локальный файл `emailspam.csv` с колонками `Category` и `Message`. Метки классов кодируются как `ham → 0`, `spam → 1`.

## Что выполнено

1. **Подготовка данных:** проверка пропусков, удаление дубликатов и кодирование целевой переменной.
2. **Исследовательский анализ:** оценка дисбаланса классов, сравнение длины сообщений, количества слов и предложений, построение корреляционной матрицы.
3. **Анализ лексики:** облака слов, частотные диаграммы и топ-15 слов по среднему весу TF-IDF для каждого класса.
4. **Векторизация текстов:** `TfidfVectorizer(max_features=3000, stop_words='english')`. Тексты преобразуются в числовые векторы с учётом значимости слов.
5. **Сравнение восьми классификаторов:** оценка качества и времени обучения на одном разбиении данных.
6. **Настройка наивного Байеса:** поиск параметра сглаживания `alpha` через `GridSearchCV` с пятикратной кросс-валидацией.
7. **Итоговая оценка:** метрики тестовой выборки, матрица ошибок и кривая обучения.

Длина сообщения, число слов и предложений используются для анализа данных. На вход классификаторам передаются только TF-IDF-признаки текста.

## Результаты

Данные разделены на **70% для обучения** и **30% для тестирования**, `random_state=42`. Для моделей, где это предусмотрено в коде, применяется `class_weight='balanced'`.

Precision, Recall и F1-score ниже рассчитаны для класса **spam**. Accuracy показывает долю правильных ответов по обоим классам.

### Сравнение базовых моделей

| Модель | Accuracy | Precision | Recall | F1-score | ROC-AUC | Обучение, с |
|---|---:|---:|---:|---:|---:|---:|
| Логистическая регрессия | 97,55% | 0,8947 | 0,9212 | 0,9078 | 0,9898 | 0,0578 |
| SVC, линейное ядро | 97,55% | 0,9146 | 0,8966 | 0,9055 | 0,9912 | 56,0326 |
| SVM, RBF-ядро | 97,80% | 0,9721 | 0,8571 | 0,9110 | 0,9905 | 131,3447 |
| **MultinomialNB** | **98,06%** | **0,9943** | **0,8571** | **0,9206** | **0,9883** | **0,0517** |
| Случайный лес | 97,80% | 0,9774 | 0,8522 | 0,9105 | 0,9898 | 10,2604 |
| K-ближайших соседей | 90,50% | 1,0000 | 0,2759 | 0,4324 | 0,7989 | 0,0091 |
| Дерево решений | 94,70% | 0,7619 | 0,8670 | 0,8111 | 0,9131 | 5,7920 |
| Гистограммный градиентный бустинг | 96,38% | 0,8267 | 0,9163 | 0,8692 | 0,9773 | 29,0817 |

Среди базовых моделей `MultinomialNB` получил лучшие Accuracy и F1-score при небольшом времени обучения. Время приведено для сохранённого запуска и зависит от оборудования и окружения.

### Модель после настройки

Для `MultinomialNB` перебирались значения `alpha`: `0.01`, `0.1`, `0.5`, `1.0`, `5.0`, `10.0`. Критерий выбора — средняя Accuracy на пяти блоках кросс-валидации обучающей выборки.

Лучшее значение — **`alpha=0.1`**, средняя Accuracy на кросс-валидации — **98,06%**.

| Метрика на тестовой выборке | Значение |
|---|---:|
| Accuracy | **98,51%** |
| Precision для спама | **0,9545** |
| Recall для спама | **0,9310** |
| F1-score для спама | **0,9426** |
| ROC-AUC | **0,9906** |

После настройки модель обнаруживает около **93,1% спама**, а среди сообщений, отнесённых к спаму, около **95,45% действительно являются спамом**. По сравнению с базовым наивным Байесом полнота выросла с 0,8571 до 0,9310, а F1-score — с 0,9206 до 0,9426. При этом Precision снизилась с 0,9943 до 0,9545: улучшение обнаружения спама сопровождается увеличением доли ложных срабатываний среди положительных предсказаний.

## Основные выводы

- В исследуемой выборке спам-сообщения в среднем длиннее обычных: около **137 символов против 71** и **28 токенов против 17** по подсчёту NLTK.
- При дисбалансе классов одной Accuracy недостаточно. Например, KNN получил Precision 1,0, но обнаружил только 27,59% спама.
- Сочетание TF-IDF и наивного Байеса показало высокое качество в проведённом эксперименте при небольших затратах на обучение.
- Подбор параметра сглаживания улучшил баланс Precision и Recall и повысил итоговый F1-score.

## Ограничения и дальнейшее развитие

В текущем коде TF-IDF обучается на всей очищенной выборке **до** разделения на обучение и тест. Поэтому словарь и веса IDF учитывают тестовые тексты, что создаёт утечку информации и может завышать метрики. Это относится и к кросс-валидации на заранее рассчитанных признаках. Для более строгой оценки следует разделять исходные тексты, а векторизацию и классификатор объединить в `Pipeline`, обучаемый внутри каждого блока кросс-валидации.

Модели сравниваются на одной тестовой выборке, которая также используется для итоговой оценки выбранного подхода. Для независимой проверки результата полезен отдельный финальный набор данных. При разбиении также стоит использовать `stratify=y`, чтобы сохранять соотношение классов.

Проект исследует англоязычные SMS. Качество на русскоязычных сообщениях, электронной почте и новых типах спама отдельно не проверялось. Следующие шаги — повторная оценка без утечки данных, проверка на свежих сообщениях и сохранение обученного пайплайна для использования в приложении.
